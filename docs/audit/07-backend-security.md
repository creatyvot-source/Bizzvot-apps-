**Bottom line**

* **cogcard** is in reasonable shape at its core:
  * every API route checks the role and the resource owner;
  * session revocation uses a tokenVersion;
  * cookies are httpOnly and Secure;
  * URLs are sanitised both when saved and when rendered;
  * uploaded images are checked by magic bytes and re-encoded.

  Its serious problems are:
  * a **privacy leak**: reviewer email is exposed on the public reviews endpoint;
  * **mass assignment of `status`**: owners can re-enable cards that an admin or billing disabled;
  * **account enumeration and lockout abuse**;
  * a **host-header-driven internal fetch** that can leak the middleware secret;
  * **custom-domain verification that the platform answers for itself**.
* **nfcwebsiteecom- is not production-safe.** It has:
  * a committed **customer PII export** (privacy incident);
  * **17 admin API routes with no authentication**;
  * **prices and discounts trusted from the client** at checkout;
  * a **stored-XSS chain** through unauthenticated writes;
  * no rate limiting anywhere.
* **The nfc-landing-page commerce flow is the best of the three.** Prices are computed on the server, Razorpay amount and status are verified, order access links are signed, and requests are rate-limited. Only Low items remain there.

## 4. Prioritised remediation plan

### P0 — within 24–48 h (incident response)
1. **C-01 PII exports:** remove both files and purge them from history (`git filter-repo --path orders_export_1.csv --path transactions_export_1.csv --invert-paths`). Force-push and invalidate old clones and forks. Find out the repo's visibility and access history. Decide with counsel on DPDP breach assessment and notification. Add `.gitignore` rules for exports.
2. **H-05 seed credential:** rotate the ecommerce admin password and any reused passwords. Purge the literal together with step 1.
3. **C-02 unauthenticated admin APIs:** before the next deploy, add an admin guard to all 17 routes (or an `/api/admin/**` matcher in `proxy.ts`). Until it ships, block `/api/admin/` in nginx for everyone except admin IPs.
4. **C-03 / H-03 checkout pricing and payment binding:** compute totals on the server from the DB and bind the Razorpay amount to the stored order total. Until then, consider disabling online checkout and COD on nfcwebsiteecom-. Use the landing flow (`nfc-landing-page`) for NFC product sales, since it already does this correctly.
5. **C-04 XSS chain:** after step 3, sanitise product HTML and limit upload types. Check existing products, pages and media for injected content.

### P1 — within 1–2 weeks
6. **H-01** Public review DTO without `reviewerEmail`, plus a regression test (spec §20).
7. **H-02** Card status split (`disabledByAdmin` / `disabledByBilling`) and removal of `status` from owner write schemas. This blocks the billing work (spec §11).
8. **H-04 / H-06 / H-07** (ecommerce): a rate limiter plus OTP attempt limits; session-only identity for returns, loyalty and carts; mandatory, timing-safe Delhivery webhook secret.
9. **M-01 / M-02** Generic login responses, constant-time compare and an atomic, abuse-resistant lockout.
10. **M-03** Fixed internal origin for middleware fetches. **M-04** TXT-only verification for custom domains.
11. **M-07** Set and enforce the proxy-trust env vars in production.

### P2 — within the next release
12. **M-05** One shared public-visibility function (owner status, locks, future privacy), used by card, vCard, review, resolve-host and track-click.
13. **M-06** Body-size caps and a media model with the spec's count limits (5 gallery images, 10 PDFs, 5 videos), signature checks and orphan cleanup.
14. **M-08** Guard the seed script for production and remove its default credentials.
15. **M-09** Card and directory visibility, an AuditLog, retention TTLs, account deletion and an analytics disclosure (spec §7, §16).
16. **M-10 / M-11 / M-12** Pin dependencies and add audit to CI; add security headers to ecommerce; lock down or delete `firestore.rules`.

### P3 — hardening backlog
17. All Low items (L-01 to L-17). The ones with the most value are L-01 (JWT type, algorithm pin, refresh rotation), L-03 (Origin check), L-04 (nonce CSP), L-06 (zod everywhere plus `sanitizeFilter`) and L-09 (media URL allow-list).

### Tests to add (map to spec §20)
* An anonymous call to every `/api/admin/**` (ecommerce) and `/api/v1/admin/**` (cogcard) route returns 401/403.
* The public review JSON has no `reviewerEmail`, `ipHash` or `repliedBy`.
* After a super-admin disable, an owner `PATCH {status:"active"}` is rejected.
* Login for an unknown, locked or suspended account returns a body and status identical to a wrong password, with similar timing.
